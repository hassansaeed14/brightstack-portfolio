How the pipeline works

A lightweight, transparent pipeline — deliberately simple so behavior is predictable and easy to extend, rather than a black-box model.

Text input
raw message, lowercased
→
Keyword scoring
weighted term matching per category
→
Urgency detection
flag words + phrase matching
→
Confidence scoring
based on signal strength
→
Routing decision
category + urgency → team

This is a rule-based classifier, not a trained neural network — I built it this way deliberately for this demo so the logic is fully inspectable. For production use, the same pipeline pattern can be swapped to use a trained text-classification model (e.g. a fine-tuned transformer) once there's enough real historical ticket data to train on — the categorization and routing structure stays the same either way.

Limitations and next steps

  • Keyword-based, not semantic — it won't catch category signals phrased in unusual or indirect ways that don't include the trained keywords.
  • English only — would need separate keyword sets or a multilingual model to handle other languages.
  • Small test set — 60 labeled examples is enough to validate the approach, not enough to guarantee performance on edge cases at scale.
  • Next step for a real deployment — collect a larger labeled dataset from actual support tickets, then evaluate whether a trained ML model improves accuracy enough to justify the added complexity.
